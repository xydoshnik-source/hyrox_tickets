# HYROX Seoul and Shanghai Ticket Watcher

Бот следит за двумя событиями в одной категории:

- `AirAsia | HYROX Seoul | Season 26/27`, `13-15 November 2026`;
- `ZhongAn HYROX Shanghai | Season 26/27`, `31 October - 1 November 2026`;
- категория в обоих случаях: `Men's Open Singles / HYROX MEN`.

`Doubles`, `Mixed`, `Pro`, `Relay`, `Adaptive` и женские категории не проверяются.

## Как определяется наличие

Скрипт открывает сам checkout Vivenu и читает его структурированные данные. Он проверяет одновременно:

1. что checkout относится именно к нужному городу;
2. что найдена точная позиция `HYROX MEN` с ключом `SOLO_OPEN_M`;
3. что позиция активна и не скрыта;
4. что checkout вернул положительный остаток по этой позиции.

Только тогда результат считается `билет есть`. Нулевой или отрицательный остаток означает `билетов нет`. Ошибка сети, изменившаяся структура checkout, отсутствие точной категории или отсутствие данных об остатке дают отдельный результат `проверка не удалась`.

## Расписание и Telegram

GitHub Actions запускает реальную проверку 10 раз в сутки, поэтому бот работает и при выключенном MacBook.

- При переходе из состояния без билетов в состояние с билетами бот немедленно отправляет отдельное однострочное сообщение.
- Один раз в сутки, после проверки в `10:36 MSK`, бот отправляет короткую контрольную квитанцию.
- Повторный запуск того же ежедневного задания не создает вторую квитанцию за ту же московскую дату.
- Ручной запуск может отправить отдельную тестовую квитанцию.
- Изменение кода проверки запускает одну тестовую квитанцию; state-коммиты этого не делают.

Каждое Telegram-сообщение состоит из одной строки со статусом обоих городов, например:

- `Seoul — нет. Shanghai — нет.`;
- `Seoul — нет. Shanghai — БИЛЕТ ЕСТЬ.`;
- `Seoul — нет. Shanghai — ошибка проверки.`

URL, время, остатки и ошибки остаются только в state-файле и логах GitHub Actions.

## Ручной запуск

В GitHub:

`Actions -> HYROX Ticket Watcher -> Run workflow`

Параметр `Send a test receipt to Telegram` по умолчанию включен. Такой запуск выполняет настоящую проверку checkout и отправляет ее результат в Telegram.

## Секреты GitHub

В `Settings -> Secrets and variables -> Actions` должны существовать:

```text
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
```

Значения секретов не хранятся в репозитории и не печатаются в лог.

## Проверка кода

```bash
python3 -m unittest discover -s hyrox-ticket-agent/tests -v
python3 -m py_compile hyrox-ticket-agent/check_hyrox.py
```

Текущее состояние обоих отслеживаемых событий хранится в `hyrox-ticket-agent/state/status.json`.
